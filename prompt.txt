ipc binding procudure
ipc binding and types porting is done by components registering themselves during execution instead of a central registry:
    When first run or main is edited, `build-main/index.js --export-types` need to be run so renderer gets the newest type defs.
    main process first import most of its files.
    Each module register its exposed methods and types.
    main process generates types dynamically.
    When there is process argument --export-types, main process writes to build-defs/ and exits.
    Starts electron window.

all methods in main that are exposed follows such signiture:
async function load(data : DataType, onProgress? : (message:ProgressType)=>void, abortSignal? : AbortSignal) : Promise<ReturnType>{}
each function exposed register itself, its path shown to renderer, data type, progress type, return type.

the renderer packages received methods giving them types and at runtime allocates a map for progress message channel and abort signal message channels.
renderer application implementation should comfortably use 
```
console.log((await ipc_manager.listInstances({id:"123"},console.log)).message);
// invokes e.g. globalThis.api.listInstances({id:"123"}, allocated_channel, null)
```
or
```
const {prom, abort} = ipc_manager.abortable.search({id:"123"}, console.log);

```
